Require AzureRM v5 and Terraform >= 1.16.0; migrate subnet service endpoints to the v5 block schema

## Migration guide

This major release requires AzureRM `~> 5.0` and Terraform `>= 1.16.0`.
Update the module source to `~> 8.0`, update the root configuration's provider
constraint to `~> 5.0`, and upgrade Terraform before initializing:

```hcl
terraform {
  required_version = ">= 1.16.0"

  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "~> 5.0"
    }
  }
}

module "function_app" {
  source  = "pagopa-dx/azure-function-app/azurerm"
  version = "~> 8.0"
}
```

Back up the Terraform state, then run `terraform init -upgrade` and review
`terraform plan` before applying. AzureRM v5 changes subnet service endpoints
from the `service_endpoints` list to `service_endpoint` blocks; the module
performs this internal schema migration without changing its inputs, outputs,
or Terraform resource addresses. No `terraform state mv`, `state rm`, or import
is required. The plan must not replace the Function App, staging slot, storage
accounts, or subnet; stop and investigate if any of these replacements appear.

AzureRM v5 also defaults resource provider registration to `none`. If the
calling configuration relied on the v4 provider's implicit registration,
configure the required resource provider registrations explicitly in its
AzureRM provider block.

The module retains `public_network_access_enabled` for its storage accounts
because AzureRM 5.0.0 does not expose the later `public_network_access`
argument. Later AzureRM v5 releases deprecate this property for removal in
v6; switching to the replacement requires raising the module's provider floor
above 5.0.0.
