azure_storage_account: major

Add AzureRM v5 support to the Storage Account module. The provider minimum is
`~> 5.8` because the module now uses `public_network_access`, which replaces the
deprecated `public_network_access_enabled` property. Terraform `>= 1.16.0` is
required.

### Migration guide

1. Update the module source version to `~> 6.0`, set the AzureRM provider
   constraint to `~> 5.8`, and use Terraform `>= 1.16.0`. Run
   `terraform init -upgrade`.
2. The `static_website` module input is unchanged, but AzureRM v5 manages it
   with a separate resource. If static website hosting was already enabled,
   keep `static_website.enabled = true` and import the existing website before
   planning:

   ```sh
   terraform import \
     'module.<module_name>.azurerm_storage_account_static_website.this[0]' \
     '/subscriptions/<subscription_id>/resourceGroups/<resource_group>/providers/Microsoft.Storage/storageAccounts/<storage_account>'
   ```

   Replace `<module_name>` with the module block name (and include any `count`
   or `for_each` instance key). This import adopts the existing website
   configuration without disabling it or recreating the storage account. New
   websites do not need an import.
3. When static website hosting is enabled, at least one of `index_document` or
   `error_404_document` must be a non-empty value.
4. Review `terraform plan` before applying. The storage account and its
   data-bearing resources must remain in place; stop if the plan proposes to
   replace or destroy them.
