azure_api_management: major

Simplify the Azure API Management module contract for the next major release. The module now owns APIM subnet creation, public IP creation when required by the selected use case, private DNS zone lookup in the current subscription, monitoring defaults, management locks, publisher notifications, Application Insights connection string lookup, and simplified hostname certificate inputs.

### Migration from 4.x to 5.x

- Replace the `virtual_network` name/resource-group object with the full virtual network resource ID. Remove `subnet_id` and `subnet_pep_id`: the module creates the APIM /24 subnet and derives the private endpoint subnet ID using the standard `pep` subnet name.
- Remove `virtual_network_type_internal`, `enable_public_network_access`, and `public_ip_address_id`. Networking is selected by `use_case`; `high_load` creates a Standard static public IP, while `cost_optimized` uses a private endpoint. Review the network changes before applying.
- Remove `private_dns_zone_ids`. The module computes fixed Azure API Management zone names and the private endpoint zone ID from the VNet subscription and `private_dns_zone_resource_group_name` (defaulting to the VNet resource group).
- Replace `monitoring` with `log_analytics_workspace_id`, required for `cost_optimized` and `high_load`. Existing metric-alert defaults and the `metric_alerts` / `metric_alert_thresholds` overrides are preserved.
- Remove `notification_sender_email` and `lock_enable`. Notifications use `publisher_email`; management locks are enabled for production use cases and disabled for `development`.
- Remove `management_logger_application_insight_enabled`, `application_insights.enabled`, and `application_insights.connection_string`. Set `application_insights.id` to enable the logger and resolve its connection string internally.
- Remove `key_vault_id` and `certificate_names`. Rename each custom hostname's `key_vault_id` to `key_vault_certificate_id`; versioned certificate IDs are normalized internally. Replace the `hostname_configuration.proxy` list with `{ use_resource_name_as_default = true }` if needed; the proxy hostname is always the APIM resource-name hostname.
- Update the module version constraint to `~> 5.0`, require Terraform `>= 1.16.0`, and set the caller's AzureRM provider constraint to `~> 5.0`. Upgrade all modules in the same root to compatible provider constraints, then run `terraform init -upgrade`.

AzureRM v5 no longer registers Resource Providers by default. Ensure the providers required by the configuration are registered, or configure registration explicitly in the caller's AzureRM provider.

Private DNS A records now use `private_dns_zone_id`, computed from the VNet subscription, DNS resource group, and fixed zone name. The provider reads existing record IDs and derives that attribute during refresh. This provider-schema change does not require imports or state moves; retain the lower contract layer's resource-address migration guidance and review a normal refreshed plan. Do not apply a plan that replaces APIM or an existing subnet.

The committed example intentionally references registry module `~> 5.0`. That next major must be published before the registry example can initialize. Pre-publication validation uses a temporary local module source override, restored before commit.

Existing deployments need special care: the new module-managed subnet and public IP are not automatically adopted from caller-managed resources. Review a Terraform plan and migrate ownership explicitly where appropriate to avoid unintended subnet conflicts or APIM replacement. No state migration is performed automatically.
