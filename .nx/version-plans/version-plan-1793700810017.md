Require validated code owners for organization initialization and align CODEOWNERS with deployment reviewer teams.

## Migration guide

Existing unattended organization initialization commands must add one or more repeatable --code-owner flags, for example: dx init --name my-project --owner pagopa --code-owner @pagopa/product-team --publish. Personal namespaces automatically include @owner and may add individual code owners. Non-interactive init leaves scaffolds local unless --publish is supplied.

Owner existence and team visibility/organization are validated before scaffolding. Effective repository Write access is intentionally deferred to manual authorization: open a PR in pagopa/eng-github-authorization granting the same teams/users Write access (or higher) and completing repository/App registration. Other organizations must use their own authorization process. No authorization PR or permission grant is automated.

The existing repository Terraform module still queries organization teams; personal CODEOWNERS generation is covered, but end-to-end personal publication remains limited by that existing dependency. This release does not change the Terraform module.
