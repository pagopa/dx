Require AzureRM v5 and drop v4 support in this module and its examples/tests.

## Migration guide

Upgrade the root `hashicorp/azurerm` requirement to `>= 5.0.0, < 6.0.0` and select v5-compatible versions of every module and transitive dependency before adopting this major. Retain Terraform `>= 1.16.0`, or any higher minimum already required by your configuration. Run `terraform init -upgrade`, commit the updated `.terraform.lock.hcl`, and review `terraform plan` and the AzureRM v5 upgrade guide before applying. No production resource addresses are renamed by this change.

Examples reference the planned v5-only VPN major and take existing Azure foundation values through a required `azure` input, isolating separately managed foundation modules from this provider graph. AWS fixtures use the VPC module with one NAT gateway for development and one per availability zone for HA, avoiding the legacy DX AWS provider required by older Core Infra versions. For an already-applied example, explicitly migrate state ownership of previously managed foundation resources before applying the revised example; do not apply or destroy it as a shortcut. This is an example-fixture migration, not a runtime VPN resource-address change. Registry initialization must wait for the intended major to be published and indexed; development checks use temporary local module sources.

These v5-only majors are planned for a future release. Older dual-compatible module versions remain usable during the published AzureRM v4 support window ending 31 December 2026. This change does not migrate modules that still require v4.
