Expose the GitHub App token as an explicit output instead of exporting it to
every subsequent job step. Consumers can also explicitly request a separate
read-only token for Terraform modules hosted in the `pagopa-dx` organization.

## Migration guide

Read the token from the `github_app_token` output and pass it only to steps that
require GitHub App access:

```yaml
- name: Cloud Login
  id: cloud-login
  uses: pagopa/dx/actions/csp-login@main

- name: Run GitHub command
  env:
    GITHUB_TOKEN: ${{ steps.cloud-login.outputs.github_app_token }}
  run: gh api user
```

Terraform workflows that download DX Registry modules must set
`create_github_modules_token: "true"` and pass the `github_modules_token`
output to the authenticated command. The GitHub App must be installed in
`pagopa-dx` with read access to the module repositories; the caller's automatic
`GITHUB_TOKEN` cannot authorize cross-repository Git downloads.

Newly generated bootstrapper workflows use the same dedicated module token for
Terraform initialization.
